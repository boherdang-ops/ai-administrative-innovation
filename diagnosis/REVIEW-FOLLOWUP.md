# 검토 의견 반영 및 후속 과제

기준: 2026-10-19 업로드한 「검토 의견」 및 행정 상황판단형 전환 논의.

## 이번 반영

| 항목 | 반영 내용 | 검증 기준 |
| --- | --- | --- |
| 응답 유도 줄이기 | 개인 문항의 목적·판단 기준을 입력 화면에서 제거하고 결과의 ‘질문과 해석 관점’에 배치 | 시나리오 응답 전에는 정답 해설이 보이지 않음 |
| 질문 이해 보존 | 기관·과정의 복합 요건은 ‘이번 문항의 확인 범위’로 안내 | 범위를 읽고도 어느 조건을 묻는지 이해할 수 있음 |
| 순서에 의존한 안내 오류 | ‘첫 번째/두 번째 답변’ 대신 실제 확인 상태를 기준으로 안내 | 선택지 순서와 안내가 충돌하지 않음 |
| 응답 분포 세분화 | 기존 supported 응답을 ‘도움받아 수행·일부 경험’으로 별도 표시 | 능력의 도움 필요와 경험의 제한 범위를 구체 해석에서 구분, 미확인·미응답 별도 유지 |
| 해석 가독성 | 반복 인용·조사 오류가 있는 문장 틀을 없애고 영역별 상태를 묶어 설명 | 실제 선택 답변은 근거 목록으로 보존, 업무 의미·행동·확인 기준 유지 |
| 공통 단서 정리 | 결과의 공통 해석 한계를 상단 ‘결과 읽기’에 통합 | 업무 환경 제약·적용 범위 등 개별 해석에 필요한 정보는 유지 |
| 기관 결과 정보량 | 확인된 선행 과제와 미확인 항목 수를 함께 표시 | 미확인이 있어도 이미 확인된 부족을 숨기지 않음 |
| 착수 표현 | 새 결과의 ‘바로 진행 가능’을 ‘선행 조건 확인 · 착수 전 점검’으로 표현 | 운영 배포 승인으로 오해하지 않음. 판정 코드와 필수 요건은 유지 |
| 과정 선택 맥락 | 기관 기본 12문항과 선택 과정의 추가 점검을 명시 | 과정이 미정이면 선택 없이 기본 진단 가능 |
| 호환성 | 새 진단에 표시 버전 고정. 이전 진단은 이전 결과 화면 사용 | 이전 임시저장 복구·대상 안내 왕복에서 문항·응답·해석 버전 보존 |

현재 문항·선택지·점수·판정 코드는 바꾸지 않는다. 이번 변경은 측정 타당성의 검증 완료를 뜻하지 않는다. CMS의 기존 편집값은 유지하고, 새 화면 문구는 공통 문구 관리 목록에 추가한다.

## 상황판단 문항 재설계 초안

아래는 전문가 검토·시범 응답용 초안이다. 공개 문항이나 채점 규칙에 반영하지 않는다. 각 보기의 길이·표현·정답 위치도 시범 검토 시 조정한다. 점수와 사람에 대한 등급을 확정하지 않는다.

### P03: 조례 근거 확인

상황: AI가 수당 지급 근거로 조례 조항을 제시했으나 원문·시행일을 확인하지 못했다. 결재 초안 제출이 임박했다. 가장 먼저 할 행동은?

- AI에 조례 번호와 링크를 다시 요청하고 받은 링크를 근거로 기재한다.
- 다른 AI에서도 같은 설명이 나오면 두 결과의 일치를 근거로 사용한다.
- 공식 원문에서 조항·시행일·적용 조건을 대조하고 확인될 때까지 해당 근거 사용을 보류한다.
- 같은 이름의 조례가 존재하는지 검색한 뒤 세부 조항은 결재 검토 단계에서 확인하도록 넘긴다.

검토 관점: 근거의 존재, 최신성, 적용 조건을 구분하는가. 원문을 직접 확인하는 작업과 생성 답변의 반복 확인을 구별하는가.

### P06: 업무 개선 우선순위

상황: 정기보고 초안 작성은 빨라졌지만 자료 대조와 부서 회신 대기로 전체 일정은 그대로다. 다음 개선 대상을 어떻게 정할까?

- 요청문을 더 세밀하게 바꿔 초안 생성시간을 먼저 줄인다.
- 최근 보고 한 건의 자료 준비·회신 대기·작성·검토 시간을 나누어 병목과 사람의 결정 지점을 확인한다.
- 유사 기관의 자동화 도구를 먼저 도입한 뒤 기존 절차를 맞춘다.
- 담당자들이 가장 불편하다고 느끼는 단계를 투표로 정해 바로 자동화한다.

검토 관점: 현행 업무 근거를 확인하는가. 체감과 실제 병목, 도구 교체와 절차 개선을 구분하는가.

### P09: 복지 상담 일지 취급

상황: 독거노인 상담 일지에는 성명·주소·병력·가족관계가 있다. 외부 AI에 입력해도 되는지는 아직 확인하지 않았다. 가장 먼저 할 행동은?

- 업무용 계정을 사용해 원본을 입력하고 답변 파일만 내부에 보관한다.
- 이름·주소를 가린 뒤 상담 내용은 그대로 입력한다.
- 외부 입력을 보류하고 담당자에게 자료·도구 허용 범위를 확인한다. 그동안 실제 개인정보가 없는 가상 사례로 요약 방식을 시험한다.
- 외부 입력은 하지 않고 수작업 처리로 확정하며 허용된 다른 방식은 검토하지 않는다.

검토 관점: 일부 마스킹을 안전 보장으로 오인하지 않는가. 확인 전 보류와 일률적 사용 포기를 구분하는가. 승인·처리 조건이 다르면 적절한 선택도 달라질 수 있음을 반영한다.

### P12: 수치 검증

상황: AI가 작성한 집계표와 자체 검토 결과는 일치한다. 원자료와 산식은 아직 대조하지 않았다. 제출 전 무엇을 할까?

- 동일 AI가 두 번 확인했으므로 검증 완료로 표시한다.
- 다른 AI에서 같은 합계가 나오면 원자료 대조를 생략한다.
- 표본 몇 줄의 문장과 형식을 확인한 뒤 전체 수치도 정상으로 처리한다.
- 핵심 수치를 원자료·산식으로 별도 검산하고 오류 발견 시 범위를 넓혀 확인한 뒤 사용 여부를 결정한다.

검토 관점: 독립된 근거와 재생성 결과의 일치를 구분하는가. 확인 범위와 최종 사용 책임을 설명할 수 있는가.

### P15: 효과 보고

상황: 한 업무의 초안 시간은 줄었지만 검토·수정·유지관리 시간은 측정하지 않았다. 부서장은 성과 보고를 요청했다. 어떻게 보고할까?

- 초안 시간 감소율을 전체 업무의 생산성 향상률로 보고한다.
- 초안 단계에서 확인한 변화와 미측정 시간을 나누어 보고하고 전체 작업시간을 같은 범위로 추가 측정한다.
- 초안 시간 감소에 담당자의 체감 개선을 더해 예산 절감 효과로 추산한다.
- 모든 효과 측정이 끝날 때까지 확인된 초안 시간 변화도 보고하지 않는다.

검토 관점: 확인된 효과를 적절히 보고하면서 측정하지 않은 범위로 확대하지 않는가.

## 검증 운영 메모

실무 경험이 다른 공무원을 대상으로 문항 이해 인터뷰를 먼저 하고, 다음으로 시범 응답과 짧은 공개·가상 업무 수행을 비교한다. 전문가 정답 합의, 오답 선택 이유, 영역별 정보량, 수행 결과와의 일치, 이용 시간, 모바일/인쇄 이해도를 기록한다. 표본 규모·등급 경계·문항 수는 검증 목적과 결과를 보고 결정한다. 실제 주민 개인정보나 비공개 업무 원문을 수집하지 않는다.
