# 공공 AI 역량진단 시제품

최신 개편: `draft-2026-10-19.3`. 공개 예비진단은 결과 확인·스스로 보완하는 단계로 독립 운영합니다. 전문가 진단 체험·신청·진행 연결은 공개 앱에서 제거했습니다. 관리자 진단은 별도 `admin/`에 분리했고 인증 서버 연결 전 비활성입니다. 관리자 권한을 브라우저에서 선택해 실행하는 방식은 제공하지 않습니다.

문항별 목적·판단 항목·보완 행동은 `data/question-intents.mjs`, 응답 해석은 `analysis.mjs`, 그래프·결과·인쇄 구성은 `report-view.mjs`와 `report.css`에서 관리합니다. 기존 방식의 단순 문항 나열 대신 근거·종합 해석·실행할 과제를 제시하며 결과 그래프는 점수가 아닌 응답 문항 수 분포입니다.

이하 초기 실행·설계 이력 중 전문가 ‘모의 체험’ 안내는 .3 이전 이력이며 현재 공개 화면에는 적용되지 않습니다.

현재 개발 중이며 운영 완료 상태가 아닙니다. 2026-10-19 질문·답변 불일치 수정: 신규 문항 버전은 `draft-2026-10-19.2`입니다. 질문별 선택지를 `data/question-answers.mjs`에서 관리하고 전체 대응 내용은 `QUESTION-REVIEW.md`에서 확인합니다. 이전 버전 정의는 `data/definitions/`에 보존합니다.

## 실행

Node.js 24 환경에서 `npm start` 또는 `node tools/serve.mjs` 실행 후 `http://127.0.0.1:4319/` 접속. 의존성 설치와 API 키 불필요. HTML 파일을 직접 여는 file:// 방식은 모듈 제한 때문에 권장하지 않음.

검증: `npm test` 또는 `node --test tests/*.test.mjs`.

## 운영자 검토

1. 개인·기관 선택 → 역할/범위/환경 → 기관의 과정 선택 → 응답 → 예비 결과.
2. 모의 결과는 C06 준비, C07 자료 보완, C08 미확인, C09 상충, C10 준비 사례를 보여줌.
3. 전문가 본 진단 모의 체험은 가상 전문가 배정 → 질문 → 가상 응답 → 검토 → 모의 확정 → 전달 → 개정. 실제 서버 접수·인증 화면이 아님.
4. ‘설계 검토’에서 JSON 소개·문항 문구를 변경하고 초안 버전도 바꾼 뒤 적용. 진행 중 진단은 원 버전을 유지. JSON 내보내기에는 콘텐츠 정의만 포함, 진단 응답은 포함하지 않음. 서버 게시를 수행하지 않음.
5. 결과 ‘인쇄 / PDF 저장’으로 사용자 브라우저에서 저장. 출력 결과·표·긴 문장은 운영 전 다시 점검.

`DECISIONS.md`는 미확정 정책, `COURSE-READINESS.md`는 원본 연결, `data/definition.mjs`는 문항 명세, `engine.mjs`는 판정, `expert-workflow.mjs`는 후속 서버의 도메인 초안.

## 서버 구현 경계와 후속 순서

운영 서버는 아직 연결하지 않음. 도메인 함수의 actor는 외부 요청 body에서 신뢰하지 말고 인증 서버가 생성해야 함. 현재 브라우저 모의 배정은 접근 통제가 아니며 실제 정보를 넣지 않음.

활성화 전: 인증된 principal → 저장소의 소유·배정 관계 조회 → requireRead → 명령별 권한·상태 검증 → 트랜잭션으로 원 결과 보존·새 보고서 추가·감사 이력 저장. 기관 담당자에게 개인 원문 자동 공유 금지. 연락처는 별도 동의와 비공개 저장. 접수·알림 상태 분리, 멱등 키는 응답자와 결합, 알림 재시도는 접수 재생성 금지. 보고서 전달은 본인 인증 후 열람. 로그에 응답·연락처 남기지 않음.

정의·규칙·선택지·결과 문구·추천 연결의 활성 버전은 서버에서 검증·승인하고 진행 중 실행에 사본 고정. 결과 개정은 사유·근거·검토자·시각을 추가하고 원 예비 결과를 덮어쓰지 않음. 저장소 동시성·낙관적 버전 잠금, 동의·보유기간, 오류·재시도·삭제 정책 결정 필요.

## 게시·복구

기존 GitHub Pages 저장소에 diagnosis/ 경로만 추가. .github/workflows/deploy.yml과 기존 CMS·인증·주소를 보존. main 최신 HEAD 확인 후 base tree에 새 경로를 추가하고 expected_sha를 적용해 다른 변경을 보호. 테스트·문서도 함께 추적하되 개인정보·실제 응답·자격증명은 포함하지 않음.

복구는 해당 추가 커밋을 대상으로 역변경 커밋을 만들고 main에 게시. 이전 main으로 강제 초기화하지 말 것. 법인 홈페이지에 추가한 진입 링크는 해당 JSON 항목만 역변경. 기존 콘텐츠를 과거 ZIP으로 덮어쓰지 않음.
